# ZCode 任务与自动化设计范式 · 学习笔记

> 来源：ZCode 产品文档六篇（任务与文件管理 / 自动化 / 闲时任务 / Command / Hooks / 编辑历史对话）。聚焦「可借鉴的产品与交互设计理念」。

## 1. 任务如何组织与呈现

任务的本质是被 Agent 操作过的「会话」。ZCode 用**同一份数据、多重视角**来承载它：

- **三种视图随时切换**——分组（按用户自定义主题/优先级）、工作区（任务跟着项目走）、时间线（按时间倒序找最近做过的事）。同一个任务列表不锁死在单一结构，用户按心情/场景换着看。
- **排序**让位于创建/更新时间两个维度，配合**搜索**（跨命令、会话、文件）和**自动归档**：已完成、无未读、未置顶且超过保留期的任务自动进入归档候选（保留期可设 3/7/14/30 天）。这是「让系统自己收拾屋子」——把清理当成可配置的默认行为，而不是用户义务。

**理念**：管理的是「流动的会话历史」，而非僵硬的待办；用颜色、分组、拖拽、右键、折叠等轻量手段降低整理成本，同时保留「移动到顶部」「只显示变更文件」这类快捷键式的效率细节。

## 2. 自动化 / 定时任务 / 闲时任务的场景分层

ZCode 把「Agent 自己跑」分成两种靠**时间确定性**区分的心智模型：

- **定时任务（Scheduled）**：解决「到点该做、需要确定性」的例常工作（早起代码汇总、周五发布简报、每日风险扫描）。有 4 个现成模板降低冷启动——且模板刻意约束为**只读、只用可验证事实、证据不足就明说**。
- **闲时任务（Idle）**：不排时间，排队等算力富余时**免费**执行——把「不紧急、可延后」的活儿变成算力峰谷的填缝机会，产品层面首次把「空闲算力」作为一种可消费的资源呈现给用户。

**创建方式的并轨**：同一件事有三种入口——表单、在会话里用自然语言创建（并绑定到当前会话、结果回投）、模板预填。界面上没有「最多跑 N 次」选项，但可以**让 Agent 帮你在会话里建**——把复杂的排程委托给会理解自然语言的 Agent 本身，这是真正把「用 AI 管理 AI」落到交互上。

**贴心细节**：任务卡片显示下次运行时间（一个月内显示「3 天后」相对时间，超一个月显示日期）、「立即运行」不打乱原计划、上次没跑完不重复排队、错过一次性任务记为「跳过」而非补跑、20 条上限且 Agent 撞线时「直接停下不擅自删」、保持唤醒全局开关。这些都在**降低「无人值守跑偏」的焦虑**。

## 3. Command 与 Hooks：给「要复用和要治理」的人

- **Command** 面向把常用提示词沉淀为可复用流程的**进阶用户/团队**：`/` 唤起命令面板，命令存成 `~/.zcode/commands/*.md` 文本文件（可版本化），支持从 Claude Code 等外部 Agent **一键迁移命令资产**。理念：命令是「人话版的工具函数」，是知识在工作流中的复用单元。
- **Hooks** 面向**插件开发者与项目维护者**：它是本地子进程协议，在 `SessionStart / UserPromptSubmit / PreToolUse / PostToolUse / Stop` 等事件时机自动注入约束、做安全检查或校验产出。刻意**不给 Hook 可直接调用模型的内部对象**，用 stdin JSON in / stdout JSON + 退出码 out 的窄接口换取安全边界。理念：把「策略与治理」从产品内置下沉为可插拔的本地钩子，用户自己决定在哪些环节加护栏。

## 4. 「编辑历史对话」的可回放/可编辑体验

核心洞察：**把「发了就不能改」的对话，变成可纠偏、可回放的时间线**。

- 悬停自己的消息出现铅笔图标，编辑后**保留原任务的模型/工作区/分支/上下文**，只改指令——避免整段重来解释，让长任务在**同一个上下文里继续**。
- **连带文件重置**：若上一轮 Agent 已按错误理解改了文件，「对话 + 文件重置」会同时把改动过的文件还原再用新消息重发；文件无法安全恢复时降级为「仅重置对话并发送」。
- **撤销文件**也遵循「要么全撤、要么都不撤」——任何一个文件无法安全还原就一个都不动，**绝不让用户落到改了一半的中间态**；改动前内容缺失、用户手动改过、终端命令造成的改动三类情形被明确告知不可撤销。
- 待发送消息队列支持「退回输入框」而非原地改字。**理念**：把「改错话」和「改错文件」视为一体，用确定性的安全边界（可安全还原才还原）换取用户敢试错的底气。

## 5. 让系统像贴心助手的任务管理细节

- **时间感知**：全部按本地时区、相对时间显示，减少「在哪个时区」的认知负担。
- **冗余入口 + 最短路径**：分组整理既可拖拽又可右键，还有「移动到顶部」这种针对长列表的捷径。
- **Agent 自身也是管理工具**：排程、限次这些复杂配置可以「让 Agent 帮你建」，把工具的复杂度转嫁给 AI。
- **明确的失败语义与护栏**：跳过不补跑、权限分档（只读→完全访问）且界面常驻橙色提醒、模板只读化，处处透着「不猜、不推测、不越权」的克制。
- **让整理自动化**：自动归档、Git 状态聚合、Wiki 生成架构导读，把「日常维护」从用户身上拿掉。

---

**一句话提炼**：ZCode 的范式是「数据（会话/任务）一次产生，视图与环境皆可换」+「把 AI 当可委托的操作员与治理点」+「用确定的安全边界换取放手」，用相对时间、自动归档、冗余入口、可回放纠偏等细节，把复杂度藏在 Agent 与确定性规则背后，让产品「像知道自己该干什么的助手」。
