# ZCode 产品设计范式学习笔记（供 aigc-studio 改造参考）

> 来源：D:\software\docs\study\zcode\ 下 20 份 ZCode 产品文档
> 提炼时间：2026-08-20
> 用途：指导把 saiOS 从"功能堆砌"改造为"像贴心 AI 助手"

## 一、核心体验：从"问一句"到"托付一件事"

把 AI 从「应答机器」重塑为「**可托付的协作者**」。用户给一句话目标，Agent 自己补
上下文、规划、执行、验证、收尾。信任感建立在三点：
- **单一稳定入口**（ZCode Agent 是默认智能体）
- **随时可及的多模态上下文**（`@`引用文件、`#`关联历史、`/`调用命令、`$`调用技能）
- **低门槛**（不打开项目也能直接对话）
设计精髓：把"准确表达需求"的成本从用户身上转移给系统。

## 二、目标模式：把"盯着反复说继续"变成"设目标等结果"

最独特范式。`/goal` 把**意图**（做到什么程度算完）与**过程**（要不要每步确认）分离。
- 每轮结束自动校验，**只认实据**（改出的文件、命令输出、测试结果），列计划/待办不算数
- 未达成自动接下一轮
- **可中途介入而不丢进度**：自然语言即可暂停/换向/放弃，暂停保留全部轮次与产物

## 三、记忆 / 技能 / 子智能体：三层"记忆与能力"分工

刻意不混淆：
- **项目记忆**（Agent 自动提炼、只存本机不进 Git）解决"每次要重新交代背景"
- **AGENTS.md**（手写、跟代码走）解决"需要评审共享的团队规则"
- **Skill**（SKILL.md）把固定流程沉淀成可复用标准，description 写清"什么时候用"
- **子智能体**解决"一段独立工作拆出去并行做"

UI 上都收敛到同一套符号语言（`@`/`#`/`/`/`$`），学习成本极低。

## 四、信息架构：轻量 IDE 外壳 + 对话为中枢

主界面 = 侧栏（任务列表，可置顶/分组/归档/拖拽）+ 中央对话 + 右侧浏览器/摘要面板。
关键理念是**不打断会话流**：目标/自动化面板从侧栏进入、不占会话视图。

## 五、"像贴心助手"的细节哲学

"先把用户的注意力抢回来"：
- 默认"变更前确认"档，高风险任务引导用计划模式
- 定时任务绑定同一会话集中产出，历史连"电脑未唤醒跳过"都如实记录
- 处处给边界与兜底（配额上限自停、撞上限明确告知不自作主张）
- **主动让出控制权，才换来用户的托付**

## 六、扩展与信任：Plugin/MCP/Wiki/远程/安全

- **Plugin** = 技能/命令/子智能体/MCP/Hooks 的打包容器，公开目录+个人市场，可从
  Claude Code 导入既有配置
- **Wiki** = 代码库架构导读（非文档站），每个结论带源码位置可点击跳回，增量刷新
- **远程开发/浏览器自动化** = 让 AI 从"能说"到"能干"，但用环境边界分离
- **安全操作确认** = 四档执行模式 + 细粒度授权（逐次/始终/拒绝/本会话/本项目），
  普通提问 5 分钟自动继续，权限请求与计划审批永远等到底
- **Bot Channel** = 微信/飞书接入，飞书流式卡片原地更新回答

## 对 saiOS 改造的核心启示

1. **对话为目标用户的主入口**：不如把 38 个功能页收敛到一个"AI 助手对话中枢"，
   用户用自然语言驱动，功能转为工具/技能被按需调用
2. **首页不该是功能大杂烩**：ZCode 用"侧栏 + 中央对话"，首页应是会话/目标/最近工作，
   而不是 38 个入口平铺
3. **目标模式替代"盯着继续"**：创作任务（生图/写歌/小说）应能设目标后自主推进、
   可中断恢复、只认实据
4. **符号化交互**（@/#//$）+ 记忆注入，降低表达成本
5. **任务留痕可回放**：进度、历史、失败原因如实记录，让 AI 显得可靠
