# Model Hub 重设计方案 —— 从「供应商管理器」到「AI 能力控制台」

> 2026-08-24 · 目标读者：鲸鱼 / 任何接手者
> 对象：`apps/model-hub/static/index.html`（708 行单文件，3 tab：供应商/用量/Prompts）

## 一、诊断：为什么觉得 low

| # | 问题 | 具体表现 |
|---|------|---------|
| 1 | **心智模型错位** | 后端已是"AI 能力控制平面"（五槽故障转移链 + OpenAI 兼容网关 + 账号池 + 守卫 + 备份 + 多系统接入），UI 却还是一张"供应商增删改查表" |
| 2 | **信息架构扁平** | 3 个 tab 平铺，没有层级；切换供应商、看用量、管 Prompts 全在一层 |
| 3 | **灵魂能力不可见** | v3 故障转移链是最大差异化能力，UI 上只是"主选 + 备选(✕)"两行字；降级发生过用户完全无感知 |
| 4 | **运营盲区** | grok 账号池 73 个账号的健康度/配额只能 SSH 查 sqlite；guard/backup/refresh 三定时器状态 UI 上看不到 |
| 5 | **接入门槛** | proxy 网关是给 memory-core/SillyTavern/writers 用的，但接入姿势只存在于 AGENTS.md 文档里 |
| 6 | **反馈原始** | confirm() 原生弹窗、alert 报错、toast 单条覆盖 |
| 7 | **视觉平庸** | Tailwind 默认 slate + cyan，无品牌记忆点，密度低 |

## 二、重新定位

> **AI 能力控制台（LLM Control Plane Console）**
> 一句话：*看得见每一次调用，管得住每一条链路，接得进任何一个系统。*

三个设计支柱：
1. **链路是一等公民** —— 五条能力泳道是整个界面的视觉主角
2. **运行时可观测** —— 每次调用、每次降级、每次刷新都有迹可循
3. **零构建不破功** —— 仍是单文件 + CDN 库，`systemctl restart` 即部署

## 三、信息架构（7 个区域）

```
┌────────────────────────────────────────────────────┐
│ 顶栏: LOGO │ 全局搜索(/) │ 出口节点徽标 │ proxy开关 │ 版本 │
├────────────────────────────────────────────────────┤
│ 五槽状态带(常驻): 💬文本 🎨图像 🔊语音 ── 主选·备选数·健康点 │
├────────────────────────────────────────────────────┤
│ ① 总览    ② 路由   ③ 供应商   ④ 账号池                │
│ ⑤ 可观测  ⑥ 接入   ⑦ 系统                            │
└────────────────────────────────────────────────────┘
移动端: 顶栏精简 + 底部 Tab 栏（图标+字）
```

### ① 总览 Dashboard（默认落地页）
- **KPI 四卡**：今日调用 / 成功率 / 降级次数 / 账号池今日剩余配额（数字滚动动画）
- **24h 调用迷你面积图**：按槽位分色叠放（uPlot）
- **事件流**：最近 20 条 `provider_degraded / media_failover_next / account_refreshed / backup_done / rogue_killed`
- **三 timer 心跳灯**：guard / backup / grok-refresh 各一个呼吸圆点 + 下次运行倒计时

### ② 能力路由 Routing ★标志性页面
- 五条**泳道**（text/image/audio/video/music），每条：
  - 主选大卡（左）→ 流动光点连线 → 备选小卡们（右，可拖拽排序、悬停✕移除、+添加）
  - 泳道右侧：本槽 24h 调用数 + 平均延迟 + 降级率
  - 空槽优雅态：虚线框 + "此能力暂无上游" + 「去接入」按钮（合法状态，不伪装）
- **链路演练器**：输入一段测试 prompt → 选槽 → 动画演示：候选1 变黄(请求中)→红(失败)→自动滑到候选2…最终绿色命中。把"故障转移"变成看得见的表演

### ③ 供应商 Providers
- 顶部 filter chips：全部/文本/图像/语音/TTS/停用
- 卡片网格：名称 + 类型徽标 + 默认模型(mono 字体) + 健康点 + 所在槽位角标(💬🎨) + 余额(OpenRouter $)
- 点击开**右侧抽屉**（不跳页）：基本信息 / Key 管理(脱敏+指纹) / 模型 curation / 最近探测记录 / 所属链路反查
- 卡片内联确认取代 confirm()：点删除 → 卡片变红"确认删除？[删除][取消]"

### ④ 账号池 Pools（新增，grok 先行）
- **配额热力图**：73 格矩阵，颜色=remaining/total（绿满→红空），hover 浮窗显示 token 指纹/上次刷新/失败原因
- 状态分布环图 + 总产能数字（"≈2190 图/天"）
- refresh worker 卡：timer 状态、上次结果(`73/73`)、手动触发按钮、日志尾部 live view
- 设计成通用 Pool 框架（pool_type 字段），未来其他多账号上游可复用

### ⑤ 可观测 Observability（原用量升级）
- uPlot 图表组：by_day 面积图 / by_model 条形图 / 成功率趋势线
- **调用日志流**（需后端新增，见 §六）：时间·槽·供应商·模型·延迟·结果·是否降级，实时追加
- 失败分析：Top 错误码排行（403 风控 / EOF / quota_exhausted…）一键跳转对应处置手册锚点

### ⑥ 接入中心 Integrate（新增）
- 网关名片：`http://172.17.0.1:8511/proxy/v1` 大字 mono + 一键复制
- **代码片段生成器**：选语言(cURL/Python/OpenSDK/Node) × 选场景(chat/image) → 生成即用代码块
- 消费者清单：memory-core 等已接入系统 + 各自最近调用健康点

### ⑦ 系统 System
- 备份快照表（14 份轮转：时间/大小/类型）+ 下载 + 恢复（红色危险区，双重内联确认）
- 导出/导入配置（现有功能迁移至此）
- 运行环境卡：版本 / Python / sqlite 路径 / SAIOS_DB_URL 连通性

## 四、交互细则

| 场景 | 现状 | 改为 |
|------|------|------|
| 切换供应商 | confirm() 弹窗 | 卡片内联黄色确认条（2 步内完成） |
| 批量/危险操作 | alert | 右下堆叠 toast + 进度条（批量刷新可见进度） |
| 全局搜索 | 无 | `/` 呼起，搜供应商名/模型名/槽位，回车直达 |
| 键盘 | 无 | `1-7` 切区域、`g r` 跳路由页 |
| 加载 | 白屏等待 | 骨架屏 shimmer |
| 空槽 | 无提示 | 明确"不可用"状态而非隐藏 |

## 五、视觉语言

- **基调**：深空黑 `#0B0F17` 底 + 双层面板 `#131A26` / `#1A2332`，1px 描边 `rgba(255,255,255,.06)`
- **主色**：青→靛渐变 `#22D3EE → #818CF8`（用于激活态、链路光点、LOGO）；语义色 绿`#34D399` 黄`#FBBF24` 红`#F87171`
- **字体**：界面 Inter/system-ui；数字与模型名 JetBrains Mono
- **密度**：紧凑 dashboard（行高 36px、卡片 padding 12px、圆角 12px）
- **微动效**（全部 CSS，零 JS 动画库）：卡片 hover 抬升 1px+描边亮起；链路光点 `background-position` 循环位移；KPI 数字 `transition` 滚动；骨架屏 shimmer
- **标志画面**：②路由页的五条泳道 = 地铁线路图隐喻，主选站大、备选站小、光点沿线路流动——这是截图发出去别人会问"这是什么工具"的记忆点

## 六、后端配套 API（hub app.py 增量，全部轻量）

| 端点 | 说明 | 数据源 |
|------|------|--------|
| `GET /api/events?limit=100` | 统一事件流（调用/降级/系统），内存 deque(maxlen=500) | proxy 与 task 钩子埋点 |
| `GET /api/calls/recent` | proxy 网关最近调用（含延迟/是否降级） | 同上 ring buffer |
| `GET /api/pools/{pool}` | 账号池聚合视图（只读 accounts.db，json.loads quota） | grok sqlite |
| `POST /api/pools/{pool}/refresh` | 触发刷新（复用 batch/refresh，返回 task_id） | grok admin api |
| `GET /api/system/timers` | 三 timer active 状态 + 上次运行 | subprocess systemctl is-active |
| `GET /api/system/backups` | 快照列表 | ls backups/ |

原则：**只读为主、ring buffer 不落盘、pools 只读 sqlite**（写操作仍走既有 admin API）。

## 八、验收标准

- [x] 打开后 **≤5 秒**能回答："五个能力分别谁在服务、健不健康"（总览 KPI + 五槽状态带，真数据）
- [x] 任何一次供应商切换 **≤2 次点击**且无需原生弹窗（内联确认体系替代 confirm()）
- [x] 发生一次真实降级后，总览页 **10 秒内**能看到事件（proxy 埋点 _emit → ring buffer → 30s 轻轮询 + 手动刷新即时可见）
- [x] 新系统接入照着⑥的代码片段 **复制即通**（cURL/Python/Node 三语言，model 自动填链首）
- [x] 手机竖屏可完成：查状态、切主选、触发刷新
- [x] 仍是 `scp 一个文件 + restart` 的部署方式（SFTP 两文件 + systemctl --user restart）
