# AI 创作工作台 saiOS 项目总结与后续规划汇报  

**汇报人：王小明   日期：2026年9月2日**  

## 一、项目一句话  

**saiOS** 是一个从零构建的全栈 AI 创作工作台（Personal AI Studio）：以「对话中枢」为统一入口，驱动文生图、视频、语音、音乐、漫画、故事、多智能体协作等真实多模态生成链路，并配套自建的多供应商模型调度中心与 GPU 算力节点。项目完整覆盖 **产品设计 → 前后端开发 → 模型接入与调度 → 云端部署运维 → 自动化测试** 的工程全链路。  

## 二、系统架构总览  

```
用户 → 公网 Nginx（多应用共存）
        ├─ 前端 React 19 + Vite + Module Federation + PWA（34 页面）
        ├─ 后端 FastAPI + SQLAlchemy(async) + 30 个 REST 模块
        ├─ 任务队列 Celery + Redis（五队列）
        ├─ 存储 MySQL + 文件卷（资产/媒体）
        ├─ 记忆服务 MemoryCore（L0-L3 分层记忆，独立容器）
        └─ 模型中心 Model Hub（自研：五槽位 + 故障转移链 + OpenAI 兼容网关）
                ├─ 云端 API 供应商池（GPT-OSS / OpenRouter / Gemini-Image / MiniMax…）
                ├─ grok2api 账号池（73 账号，每日自愈刷新）
                └─ 家庭 GPU 节点（RTX 4080S 16G，frp 内网穿透）
                      ├─ ComfyUI（Wan2.1 视频生成）
                      └─ MusicGen（音乐生成）
```

- Docker Compose 17 容器运行于腾讯云；公网仅暴露 80/443，API/DB/Redis 全部内收。
- **混合算力**：云端 API（弹性、有配额）+ 家庭 GPU（免费、开源模型），自研 Hub 统一调度、双向自动降级。

## 九、未来规划方向（自查后已定优先级）

**优先级排序：A（垂直 CV）→ E（工程规模化）→ B（Agent 深化）→ C（数据飞轮）→ D（平台化）。**
排序依据：A 已有 30.9 万帧数据资产与明确落地路径，投入产出比最高；E 是一切方向的地基（CI 缺失已经实际拖慢迭代）；C、D 依赖"有多用户"这个前提，当前单人使用，先缓。

- **A. 垂直 CV 落地（第一优先，进行中）**：完成 PPE 检测模型自训后，研究"边缘部署 vs 云服务化"方案的权衡。**研究问题**：如何在延迟、带宽和维护成本之间找到平衡点？**拟解决思路**：设计混合部署框架——延迟敏感推理放置在家庭 GPU 节点，本地实时检测，云端负责日志汇总和模型更新；构建评估模型，根据网络环境和任务类型动态切换执行。
- **E. 工程规模化（第二优先）**：提升系统的可维护性和扩展性。**研究问题**：现有项目单体结构下，如何引入 CI/CD 和可观测性工具，并评估是否拆分为微服务？**拟解决思路**：逐步搭建 CI/CD 流水线，实现代码自动测试和部署；引入 APM 平台，如 Prometheus + Grafana，监控服务健康；按照功能边界适度拆分服务（如模型调度、记忆服务、界面渲染独立运行），同时评估 2C 场景家庭 GPU 环境下的可行性。
- **B. Agent 架构深化（第三优先）**：研究适合个人项目的**多智能体协作框架**。**研究问题**：在小规模系统中，如何优化记忆检索策略、多 Agent 协作评测和工具调用的可靠性？**拟解决思路**：借鉴奖励建模与基准评测思想，构建多 Agent 协作基准任务集（任务完成率/步数/成本三指标），对不同记忆检索方案和工具链健壮性进行对照实验；据实验结果迭代优化协作策略。
- **C. 数据飞轮（暂缓，有用户后启动）**：探索用户创作数据的规范化沉淀与再利用。**研究问题**：如何合法合规地将用户创作行为转化为模型微调或推荐素材？**拟解决思路**：近期先落地数据分级和脱敏策略与用户授权管道，建立匿名化的数据流水线；其次开发自动标注工具和反馈机制，将优质创作提升为训练语料；联邦学习等隐私计算作为远期探索方向。
- **D. 从工具到平台（暂缓，同上）**：规划多租户与运营体系建设。**研究问题**：在保证可用性和安全合规的前提下，如何实现用户隔离、配额计费和内容审核？**拟解决思路**：设计多租户架构，确保不同租户资源隔离；制定使用量监控和配额机制，以简单的计费或积分体系引导用户；引入自动化审核规则，通过模型筛查或关键词过滤检测违规内容，同时保留人工复核流程。

### 面向工程型导师  

本稿件示例在原有汇报基础上，新增"技术难点攻坚案例"以供工程类导师参考。以下三个案例均为真实生产事故与复盘结果（缩略版）：  

**案例一：登录 502 错误（三种形态，逐一根治）** — 云端部署后登录偶现 502。复盘定位三种形态：①**启动竞态**——nginx 先于 api 进程就绪，首批登录请求撞上 `connect() failed (111)`；**解法**：在镜像内为 nginx 增加 `wait-for-api.sh` 启动前健康等待脚本（轮询 `/api/v1/health/live` 通过后才启动 nginx），根治冷启动 502。②**容器 IP 缓存**——api 容器重建后 Docker 内网 IP 变化，而 frontend 的 nginx 缓存了旧 upstream 解析结果，出现 `upstream: http://172.18.0.3:8000` 型 502；**解法**：确立运维纪律——重启 api 必连带 `force-recreate frontend` 让 nginx 重新解析。③**网络级损坏**（`invalid IP`）——需 `compose down/up` 彻底重建 docker 网络（数据卷保留）。三形态分别对应"时序、缓存、网络"三类根因，均已固化为部署检查单。  

**案例二：反代路径劫持（多服务前缀冲突）** — 多个后端应用共用一台 nginx 时，一条 `location ^~ /api/v1` 规则被误配到另一个 Go 后端，而 saiOS 前端硬编码请求 `/api/v1/...`，导致**登录请求全被劫持到陌生服务，全线 401**；另一相关形态是根路径 `/` 被静态备案页占用，主应用 SPA 落地异常。**解法**：归还 `/api/v1` 给 saiOS，仅保留另一服务真正的私有子路径；根路径归还主应用、静态页挪至子路径。**防复发**：nginx 备份文件一律移出 `sites-enabled/`（通配加载会导致 duplicate default server 使 reload 静默失效）；建立"改配置后 grep 占位符残留 + `nginx -t` + 灰度验证"清单。**教训**：多个服务共享顶层前缀必然打架，接入前必须先确认各前端真实使用的 API 前缀。  

**案例三：跨事件循环连接池崩溃（潜伏 bug 根治）** — Celery worker 内媒体任务偶报 `got Future attached to a different loop`，且每 15 秒刷 `RuntimeError: Event loop is closed`，同 worker 第二个媒体任务必炸。定位：Celery 每任务用 `asyncio.run` 新建事件循环，而模块级 aiomysql 连接池、asyncio.Lock、redis 异步客户端在多个循环间被复用。**解法**：worker 侧 `DB_POOL_CLASS=null`（NullPool 短连接，不复用池）；所有模块级锁与异步客户端按 running loop 隔离（`WeakKeyDictionary[loop, obj]`）。API 进程为单循环模型，行为不变。**教训**：worker 侧任何模块级异步资源（池/锁/客户端）都是跨循环隐患，新增时必须 per-loop 或确认 NullPool/短连接。  

- **其他改进案例**：systemd 自愈守卫与账号池每日自愈 worker（自动刷新 73 账号配额）、任务终态通知与故障探测告警、生产事故复盘文档化流程等，可当面展开。

## 项目一页式摘要  

- **项目概览**：saiOS 是一个全栈 AI 创作平台，从对话入口驱动多模态内容创作，包含图像、音频、视频、故事、角色扮演和多智能体协作等功能。系统自研了模型调度中心和混合算力节点，实现了产品到部署的闭环开发。  
- **系统架构**：后端采用 FastAPI + Celery + Redis，前端使用 React/PWA；记忆服务（MemoryCore）独立部署分层记忆；模型中心集成多家云 API 和家庭 GPU，支持故障转移调度，保证性能和稳定性。  
- **核心成果**：实现了端到端的真实生成功能，包括对话中枢、统一 Studio（图像/漫画/语音/音乐/视频）、角色扮演、Agent 协作、AI 生命体（成长日记+长期记忆）等。资产库涵盖 10 类超过 1.3 万条资源，并搭建了灵感画廊提供一键模板和相似推荐。  
- **工程亮点**：自主研发模型中心、混合算力调度算法和运维自动化体系。系统拥有 systemd 守护、故障告警与回调、多种生产事故的复盘整改经验；家庭 RTX 4080S 与云 API 实现弹性容灾；PPE 检测：30.9 万帧预标注 + v1 训练实验完结（自蒸馏证伪，v2 路径已定）。  
- **质量保障**：完整的自动化测试覆盖，包括前端 TypeScript、Playwright 回归测试、后端 pytest；发布流程要求全面测试。当前全链路性能稳定：文本对话 8-14s 得响应，图像 23s 出图，音视频通道均可用。  
- **当前挑战**：单人项目尚未实现多租户和计费体系；监控体系简陋，缺乏专业 APM；高度依赖外部模型能力；成本核算待细化（CI 已落地：GPU 节点 push 触发 tsc+pytest 双 Job 全绿）。
